# 离线数据摆渡系统（FDT）部署说明

本文是一步步的部署 runbook。每一步给出**操作**与**为什么/注意**。设计与安全依据见 [技术方案.md](技术方案.md)。

> 术语：**内网区**＝气隙隔离、零出口；**DMZ**＝唯一联网的审批网关；**手机**＝用户自带、装飞书。文件数据永远只在内网区流动。

---

## 0. 部署总览与前置条件

### 0.1 拓扑与网络规则（先规划，后动手）

| 区域 | 部署什么 | 网络规则 |
|---|---|---|
| 内网区（气隙） | Portal、datasvc、数据库、staging 隔离区、DLP/AV、各台 ATM | **禁止**任何到互联网/DMZ 的出站；仅内网 LAN 互通；ATM 只放行到 datasvc/审计服务 |
| DMZ | 审批网关（fdt-gateway） | 仅允许：出站到飞书 OpenAPI、入站来自手机的 HTTPS、入站飞书回调；**不得**连内网区 |
| 用户手机 | 飞书 App + 网页应用（`/app/`） | 互联网 |

**为什么**：内网零出口是整个安全模型的地基。跨区只有二维码（人肉摆渡），所以内网与 DMZ 之间**没有任何网络连接**——网关不与内网数据库通信，它只处理从 QR#1 带来的元数据。

**注意**：内网区与 DMZ **不共享数据库**。网关的会话是内存态、临时的；申请单/令牌/审计都在内网库。

### 0.2 前置条件

- 一台内网服务器（Linux，跑 Portal+datasvc+DB），一台或多台 ATM 一体机（Linux）。
- 一台 DMZ 主机（Linux）跑网关，具备到飞书的出站 HTTPS 与一个公网入口（域名+证书）。
- 飞书企业租户 + 管理员权限（建自建应用、审批模板、网页应用）。
- Go 1.26+ 构建环境（可在构建机编译出静态二进制再分发，运行机无需 Go）。
- HSM（生产强烈建议，用于 `SK_网关`）；无 HSM 时先用软件密钥但风险更高（见 §3.4）。
- 内网 NTP 源（令牌有效期依赖时钟，见 §6.5）。

### 0.3 构建二进制（在构建机执行一次）

```bash
cd fdt
go build -o bin/fdt-keygen  ./cmd/fdt-keygen
go build -o bin/fdt-portal  ./cmd/fdt-portal
go build -o bin/fdt-gateway ./cmd/fdt-gateway
go build -o bin/fdt-atm     ./cmd/fdt-atm
go build -o bin/fdt-demo    ./cmd/fdt-demo
```

**为什么用静态二进制分发**：运行机（尤其气隙内网）不应装工具链，减少攻击面。把 `bin/` 拷到各主机即可。

## 1. 生成信任链密钥

在**离线、受控**的机器上执行（最好就是将来放私钥的机器/HSM 旁）：

```bash
./bin/fdt-keygen -out /etc/fdt/keys
```

产出四个文件：

| 文件 | 内容 | 部署到哪 |
|---|---|---|
| `sk_internal.pem` | SK_内网（私钥，0600） | **内网** Portal 签名服务 |
| `pk_internal.pem` | PK_内网（公钥） | **DMZ** 网关（验 QR#1） |
| `sk_gateway.pem` | SK_网关（私钥，0600） | **DMZ** 网关（签 QR#2）→ 生产应进 HSM |
| `pk_gateway.pem` | PK_网关（公钥） | **每台内网 ATM**（离线验 QR#2） |

**为什么这样分发**：私钥永不跨区。ATM 只需 `pk_gateway.pem` 就能**离线**验证放行令牌——即使 ATM 被拆机也拿不到能伪造 QR#2 的私钥。

**注意**：
- `sk_*.pem` 权限必须 0600、属主为服务运行账户；用 `scp`/介质摆渡分发，**绝不走邮件/共享盘明文**。
- 备份私钥到离线介质（保险柜），密钥丢失＝无法签发/验证，需重新初始化。
- 令牌里带 `kid`（如 `int-2026-01`/`gw-2026-01`），为将来轮换预留（见 §8.2）。

## 2. 内网数据库

### 2.1 开发/试点：SQLite（开箱即用）

Portal 启动时用 `-db /var/lib/fdt/fdt.db` 即自动建库建表（schema 幂等）。无需单独装数据库。

### 2.2 生产：PostgreSQL（需方言适配，见注意）

**当前代码的 schema 是 SQLite 方言**，直接连 Postgres 会失败。生产切 Postgres 需改这几处：

- `internal/store/store.go` 的 `schema` 常量：`INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGSERIAL PRIMARY KEY`；去掉 `?_pragma=...` DSN 参数。
- `AddFiles` 的 `INSERT OR REPLACE` → Postgres 的 `INSERT ... ON CONFLICT (...) DO UPDATE`。
- 驱动改为 `github.com/jackc/pgx/v5/stdlib`，`store.Open("postgres", dsn)`。

**为什么现在没直接支持**：试点阶段 SQLite 零运维、单文件易备份；schema 已按可移植方式编写（类型/约束贴近 Postgres），迁移是机械改动。**这是上生产前必须完成的一项**，别跳过。

**注意**：审计表 `audit_events` 建议额外落一份到 WORM/只追加存储（对象存储版本锁或专用审计库），因为哈希链能"检出"篡改但不能"阻止"有 DB 写权限者删改。

## 3. 部署内网服务（Portal + datasvc）

### 3.1 目录与权限

```bash
sudo useradd -r -s /usr/sbin/nologin fdt
sudo mkdir -p /var/lib/fdt /var/lib/fdt/staging /etc/fdt/keys
sudo cp /etc/fdt/keys/sk_internal.pem /etc/fdt/keys/   # 已在§1生成
sudo cp bin/fdt-portal /usr/local/bin/
sudo chown -R fdt:fdt /var/lib/fdt
sudo chmod 700 /var/lib/fdt/staging
sudo chmod 600 /etc/fdt/keys/sk_internal.pem
```

**前端已内嵌进二进制**（`internal/webui`，go:embed），无需再拷 `web/` 目录、也不受启动目录影响；仅当要换自定义皮肤时才用 `-web-dir` 指向外部目录。

**为什么把前端交给 Portal 托管**：页面与 API 同源（都在 `:8080`），前端用相对路径调接口，既不需要在网页上暴露"API 地址"输入框，也没有跨域(CORS)问题。用户直接访问 `http://<portal>:8080/` 即可。

**为什么单独建 `fdt` 系统用户 + nologin**：最小权限，服务被攻破也难交互登录。staging 0700 防止其他本地用户读到隔离区数据。

### 3.2 systemd 服务

`/etc/systemd/system/fdt-portal.service`：

```ini
[Unit]
Description=FDT Intranet Portal + Data Service
After=network.target

[Service]
User=fdt
ExecStart=/usr/local/bin/fdt-portal \
  -portal-addr 10.0.10.5:8080 \
  -datasvc-addr 10.0.10.5:8081 \
  -db /var/lib/fdt/fdt.db \
  -internal-key /etc/fdt/keys/sk_internal.pem \
  -staging /var/lib/fdt/staging \
  -source-root /var/lib/fdt/upload \
  -identity ldap \
  -ldap-url ldaps://dc01.corp.example:636 \
  -ldap-ca /etc/fdt/keys/dc-ca.pem \
  -ldap-service-dn 'CN=fdt-svc,OU=Service,DC=corp,DC=example' \
  -ldap-service-pass <SVC_PASSWORD> \
  -ldap-base 'DC=corp,DC=example' \
  -frame-budget 1600
Restart=on-failure
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/var/lib/fdt

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now fdt-portal
curl -s http://10.0.10.5:8080/healthz   # 期望 ok
curl -s http://10.0.10.5:8081/healthz   # 期望 ok
```

**地址说明**：`10.0.10.5` 换成你的内网 IP。Portal(8080) 面向内网用户浏览器；datasvc(8081) 只面向 ATM，**不要**暴露到用户网段。

#### 一键安装（`fdt install intranet`）如何改 Portal 网页端口

统一二进制下，内网读 `/etc/fdt/fdt.env`：

| 配置 | 含义 |
|---|---|
| `LISTEN=0.0.0.0:8080` | Portal / 管理页监听（**可改**，例如改成 `:9088`） |
| 固定 `0.0.0.0:8081` | ATM 数据口 `/data` `/import`（**不可改**；无页面，访问 `/` → 404） |

```bash
# 改网页端口后重启
sudo sed -i 's/^LISTEN=.*/LISTEN=0.0.0.0:9088/' /etc/fdt/fdt.env
sudo systemctl restart fdt
# 浏览器 → http://<内网IP>:9088/
# ATM 仍用 http://<内网IP>:8081/data 与 …/import ；LISTEN 不能设为 8081
```

旧版分进程时用 `-portal-addr` / `-datasvc-addr`（见上方 systemd 示例）。更细的端口与防火墙说明见 [一键部署.md](一键部署.md)。

**为什么 `-frame-budget 1600`**：这是单帧 QR#1 的字节预算。清单压缩后 ≤ 预算走 `full`（带逐文件清单），否则自动降级 `summary`（只带目录树+统计+Merkle根）。调大→更多请求能带全量清单，但二维码更密、更难扫；1600 是可靠扫描的稳妥值。

### 3.3 staging 隔离区与 DLP/AV

- Portal 会把上传数据**复制**进 `staging/<reqId>/` 冻结（审批与导出都基于这份快照，防止事后被改）。
- `manifest.RuleBasedDLP` 是**开发用规则引擎**，其 AV 字段是桩。生产要接真实 DLP/杀毒：实现 `manifest.Engine` 接口，在 `fdt-portal` 里替换 `portal.Service.DLP`。
- **导入方向**已实现（`internal/importer` + Portal 的 `-importer-addr` 服务）：ATM 索引U盘→内网签 QR#1→飞书审批→QR#2→ATM 流式上传到隔离区→**重算 Merkle 防换盘**→AV/DLP 扫描→通过释放到目标目录、命中则拦截。生产把 `RuleBasedScanner`（标记 EICAR/可执行）换成真实 AV/DLP 引擎，并规划隔离区/目标目录（`-quarantine`/`-target`）。

### 3.4 上传方式说明

开发版 Portal 的 `POST /requests` 接收**服务端目录路径** `sourceDir`（便于联调）。这带来"任意目录读取"风险，已用 **`-source-root` 收敛**：设置后 `sourceDir` 必须解析到该根目录之内，越界直接拒绝（`ErrSourceOutsideRoot`）。**生产必须设置 `-source-root`**（未设置时启动会打印告警），或彻底改成 **multipart 文件上传**：把上传流写入 `staging/<reqId>/` 后再跑清单管线（改动点在 `internal/portal/http.go` 的 `createRequest` 与 `Service.CreateExportRequest`，staging 逻辑已具备）。

### 3.5 启用 AD 身份认证（LDAP 绑定）

**为什么要接 AD**：默认 `-identity none` 时申请人取自请求体，谁都能冒充别人提申请。接 AD 后申请人身份经过域认证，姓名/工号/部门从目录读取，前端不再手填、也不可编辑；认证后的身份写进 QR#1 并签名，下游不可篡改，还能按部门/密级路由审批。

- `-identity ldap` 启用真实 AD；`-identity mock` 用内置样例账号（zhangsan/lisi，密码 pass123）供离线联调；`-identity none` 关闭认证（仅开发）。
- **认证流程**：Portal 用 HTTP Basic 收域账号口令 → `LDAPProvider` 先以**服务账号**搜索用户 DN，再用**用户 DN + 口令绑定**验证（search-then-bind），成功后读 `displayName/employeeID/department/mail/title`。
- 关键 flag：`-ldap-url`（建议 `ldaps://…:636`）、`-ldap-starttls`（用 `ldap://` 时升级加密）、`-ldap-ca`（校验 DC 证书的 CA PEM）、`-ldap-service-dn/-ldap-service-pass`（服务账号）、`-ldap-base`（搜索基）、`-ldap-filter`（默认 `(sAMAccountName=%s)`）。
- 字段映射：姓名=`displayName`、工号=`employeeID`、部门=`department`；如需改用 `sAMAccountName`/OU 解析，调 `-ldap-filter` 或在 `internal/identity/ldap.go` 的属性名配置里改。

**安全要求**：
- **Basic 认证必须走 TLS**（口令是 base64 非加密）。生产在 Portal 前放 TLS 终止（反代或 Portal 直接 HTTPS），或全程 LDAPS。
- **必须用 LDAPS 或 StartTLS** 连 DC，禁明文 LDAP。
- 用户名进搜索过滤器前已用 `ldap.EscapeFilter` 转义，**防 LDAP 注入**——不要绕过该函数自拼过滤器。
- 服务账号只读、最小权限（仅需在 `-ldap-base` 下读用户属性）。
- `-ldap-insecure` 仅开发用，生产禁用。
- Kerberos 依赖时钟同步；AD 认证同样要求 Portal 与 DC 时间一致（见 §6.5 NTP）。

**升级路径**：若要免密 SSO，可在 Portal 前放 nginx `mod_auth_gssapi`/Kerberos 反代，验证后传 `X-Remote-User`，Portal 改用 `Provider.Lookup` 取属性（接口已预留）。

## 4. 部署 DMZ 审批网关

### 4.1 前置条件

- DMZ 主机一台（Linux）：可**出站**到飞书 OpenAPI，可被手机侧 **HTTPS 入站**访问。
- 一个公网域名（如 `fdt-gw.corp.example.com`）+ 受信任 TLS 证书（飞书网页应用强制 HTTPS 且校验证书链）。
- 飞书企业租户管理员权限。
- 已从 §1 取得 `pk_internal.pem`（验 QR#1）；`SK_网关` 见 §4.7。

### 4.2 飞书开放平台配置（管理员操作）

> **图文逐步操作**（截图 + 官方链接 + 排错）：见 [飞书接入指南.md](飞书接入指南.md)。

**① 创建自建应用**：开发者后台 →「企业自建应用」→ 记下 `App ID` / `App Secret`。

**② 开通 API 权限**（申请后需管理员发布/生效权限版本）：

| 用途 | 权限 scope |
|---|---|
| 获取 tenant_access_token | 应用身份基础能力 |
| 创建审批实例 | `approval:approval` |
| 读取审批实例状态（轮询用） | `approval:approval`（实例只读） |
| 接收审批事件回调（可选） | 事件订阅（见④） |
| 工号→open_id 解析（如需映射） | `contact:user.base:readonly` |

**③ 创建审批定义（模板）**：表单控件须与网关 `feishu-form.json` 的 **`field` + 真实控件 `id`** 一致，否则建实例被拒。默认逻辑名见 [`config/feishu-form.example.json`](../config/feishu-form.example.json)；Portal/ATM 增删字段后的对齐步骤见 [一键部署.md](一键部署.md#改字段后飞书审批如何匹配) 与 [飞书接入指南.md §8](飞书接入指南.md#8-创建审批定义表单字段对齐)。

| 网关逻辑 field | 审批表单控件 | 建议类型 |
|---|---|---|
| `req_id` | 申请单号 | 单行文本 |
| `applicant` | 申请人 | 单行文本 |
| `dept` | 部门 | 单行文本 |
| `reason` | 事由 | 多行文本 |
| `class` | 密级（来自 Portal/ATM 的 `cls`） | 单选 |
| `merkle_root` | 数据指纹 | 单行文本 |
| `file_count` | 文件数 | 单行文本 |
| `total_size` | 总字节 | 单行文本 |
| `manifest` | 文件清单/摘要 | 多行文本 |
| （自定义） | 与 Portal `feishuField` / ATM `key` 同名 | 按类型 |

发布审批定义后记下 `approval_code`。多级/会签/按密级路由在审批流里配置（属飞书能力，不在本系统）。改模板字段须同步：**Portal/ATM 配置 → 飞书控件 → 网关 form JSON（id 换成飞书真实 id）**。

**④ 事件订阅（回调，可选但推荐）**：
- 请求地址填 `https://<网关域名>/callback`；设置 **Encrypt Key** 与 **Verification Token**（记下来填进网关）。
- 订阅审批实例状态变更事件。
- 保存时飞书会先发一个 `url_verification` 握手，网关 `HandleCallback` 会**回显 challenge**——所以**务必先启动网关，再在飞书点保存**。
- **为什么**：网关用 Encrypt Key 做 AES-256-CBC 解密、Verification Token 校验来源，防伪造"审批通过"回调骗签 QR#2（风险 C3）。
- **两条取结果的路径**：网页应用轮询 `GET /qr2` → 网关调飞书 `GetApprovalStatus`（主路径，只需②的读权限）；事件回调 `/callback`（推送，更实时、且是额外验签点）。二者都能触发签 QR#2，可只用轮询、或两者都开。

### 4.3 网关主机与网络隔离

```bash
sudo useradd -r -s /usr/sbin/nologin fdtgw
sudo mkdir -p /etc/fdtgw
sudo cp /path/to/pk_internal.pem /etc/fdtgw/     # 验 QR#1（只读）
sudo cp bin/fdt-gateway /usr/local/bin/
```

防火墙规则（DMZ 隔离，**零出口的另一半**）：

| 方向 | 规则 | 说明 |
|---|---|---|
| 出站 | 允许 → `open.feishu.cn:443`（国际版 `open.larksuite.com:443`） | 调飞书 OpenAPI |
| 入站 | 允许 互联网 → `:443`（`/app/`、`/submit`、`/qr2`、`/qr2/png`、`/jsapi/config`、`/healthz`） | 网页应用访问 |
| 入站 | 允许 飞书回调网段 → `:443/callback` | 事件推送（若启用） |
| **禁止** | DMZ → 内网区 任何连接 | 网关不得触达内网 |
| **禁止** | 内网区 → DMZ | 内网不主动连网关 |

**为什么**：网关是唯一联网组件，必须与内网**双向隔离**；否则气隙失效、零出口不成立。出站按域名/IP 白名单收敛，仅放飞书。

### 4.4 TLS（网关自带 HTTPS + Let's Encrypt，无需 nginx）

#### 推荐：绑定域名 + 内置 ACME（Let's Encrypt）

```bash
sudo ./fdt install gateway --bundle gateway.tgz \
  --domain fdt-gw.example.com --email ops@example.com
```

安装时会写入 `/etc/fdt/domain.json`（域名绑定）并启用 ACME。也可装好后打开 `/admin/`：

1. **绑定域名**（主域名 / 可选别名 / 邮箱）→ **检测 DNS 解析**
2. **为已绑定域名申请证书**（Let's Encrypt）

`fdt.env` 关键项：`DOMAIN_CONFIG`、`ACME=1`、`ACME_DOMAIN`、`ACME_EMAIL`、`ACME_CACHE`（默认 `/var/lib/fdt/acme`）、`ACME_HTTP=0.0.0.0:80`。  
网关在 **80** 做 HTTP-01 校验，在 **443** 提供 HTTPS，证书自动续期。注册链接优先使用已绑定域名的 `https://…`。

要求：域名 A/AAAA 指向本机；安全组/防火墙放行 80 与 443。

#### 备选：手动证书

`TLS=1` 时也可放置：

```
/etc/fdt/tls/fullchain.pem
/etc/fdt/tls/privkey.pem
```

或用 `TLS_CERT` / `TLS_KEY` 指向其它路径。

联调：`--mock`（`TLS=0`、`:8090`）。前面再挂 nginx **非必需**。

**注意**：飞书网页应用要求证书链完整有效。

### 4.5 凭据与密钥管理

- `pk_internal.pem`（验 QR#1）拷到 `/etc/fdtgw/`，只读。
- `SK_网关`：试点用 `sk_gateway.pem`（0600、属主 `fdtgw`）；生产进 HSM（§4.7）。
- **飞书 App Secret / Encrypt Key / Verification Token 是敏感凭据**，用 `EnvironmentFile` 注入，**不要写死在 unit 文件**。

`/etc/fdtgw/gateway.env`（`chmod 600`、`chown fdtgw:fdtgw`）：

```
FDT_FEISHU_APP_SECRET=xxxxxxxx
FDT_FEISHU_ENCRYPT_KEY=xxxxxxxx
FDT_FEISHU_VERIFY_TOKEN=xxxxxxxx
```

### 4.6 systemd 服务（Live 模式）

`/etc/systemd/system/fdt-gateway.service`（敏感值用 `${VAR}` 从 EnvironmentFile 展开）：

```ini
[Unit]
Description=FDT DMZ Approval Gateway
After=network-online.target
Wants=network-online.target

[Service]
User=fdtgw
EnvironmentFile=/etc/fdtgw/gateway.env
ExecStart=/usr/local/bin/fdt-gateway \
  -addr 127.0.0.1:8090 \
  -mock=false \
  -internal-pub /etc/fdtgw/pk_internal.pem \
  -gateway-key /etc/fdtgw/sk_gateway.pem \
  -release-ttl 72h \
  -feishu-app-id <APP_ID> \
  -feishu-app-secret ${FDT_FEISHU_APP_SECRET} \
  -feishu-approval-code <APPROVAL_CODE> \
  -feishu-encrypt-key ${FDT_FEISHU_ENCRYPT_KEY} \
  -feishu-verification-token ${FDT_FEISHU_VERIFY_TOKEN}
Restart=on-failure
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadOnlyPaths=/etc/fdtgw

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now fdt-gateway
journalctl -u fdt-gateway -n 20      # 确认日志未打印 "使用 mock 飞书客户端"
curl -s https://fdt-gw.corp.example.com/healthz   # 期望 ok
```

**⚠️ 关于 `-mock`**：现已**默认 `false`**（fail-safe）。只有显式加 `-mock` 才会用离线自动审批客户端，且启动会打印醒目告警。生产**不要**加 `-mock`，并填齐飞书凭据；启动日志确认不是 mock 模式。App Secret / Encrypt Key 用 `EnvironmentFile` 注入，勿写死。

### 4.7 SK_网关 与 HSM / 双控（生产强烈建议）

- 试点：用 §1 生成的 `sk_gateway.pem`（软件密钥）。风险：DMZ 联网，私钥文件被窃即可伪造任意 QR#2（风险 C2）。
- 生产：把 `SK_网关` 放进 **HSM**，实现 `hsm.PKCS11Signer`（当前是桩，`Sign` 返回 `ErrPKCS11Unavailable`），在 `fdt-gateway` 里用它替换 `NewSoftwareSignerFromFile`。
- **双控（two-person）**：优先用 **HSM 原生的 m-of-n 授权**（如 PED key quorum）——签名前需两名管理员各自用 PED 授权。代码里的 `hsm.DualControlSigner` 是软件版双控原语（demo 已用），但生产应由 HSM 硬件强制，别依赖软件计数。

### 4.8 网关冒烟测试

```bash
# 1) 健康
curl -s https://<域名>/healthz                       # 期望 ok

# 2) 提交一个真实 QR#1 帧（从 Portal GET /requests/{id}/qr1 取）
curl -s -X POST https://<域名>/submit -H 'content-type: application/json' \
  -d '{"frame":"FDT1....."}'                          # 期望 {reqId,instanceId,status,manifestText}

# 3) 飞书里审批通过后，轮询取 QR#2
curl -s 'https://<域名>/qr2?reqId=<reqId>'           # status=APPROVED 且含 qr2Frame
curl -sI 'https://<域名>/qr2/png?reqId=<reqId>'      # 200 + image/png

# 4) 回调握手（飞书保存事件订阅时会自动发；也可手动验证）
curl -s -X POST https://<域名>/callback \
  -d '{"type":"url_verification","challenge":"x","token":"<VERIFY_TOKEN>"}'   # 期望回显 {"challenge":"x"}
```

### 4.9 常见坑

- **建实例失败/表单空白**：审批模板字段 key 与 §4.2③ 表不一致。
- **回调一直失败**：Encrypt Key/Verification Token 不匹配；或网关未在飞书点"保存"前启动（握手 challenge 没回显）。
- **网页应用请求/图片加载失败**：证书链不全或自签未信任；H5 可信域名未配置（§5.3）。
- **审批被自动放行**：`-mock` 忘了关。
- **申请人 open_id**：`LiveClient` 默认 `UserIDType=open_id`，且把 QR#1 里的 `applicant.id`（内网工号）直接当 open_id 用；若内网工号 ≠ 飞书 open_id，需给 `NewLiveClient` 传 `applicantResolver` 做映射（当前 `fdt-gateway` 传 `nil`，即直接用 QR#1 的 id）。

### 4.10 多租户 / SaaS 部署（一套网关服务多客户）

若由你方托管**共享网关**服务多个客户（每客户仍是独立飞书组织、独立内网）：

#### 推荐：运营建租户 + 客户注册 + 租户后台自助维护

1. 安装网关（会生成 `ADMIN_PASSWORD` 并打印一次）：

```bash
sudo ./fdt install gateway --mock          # 联调
# 或生产：sudo ./fdt install gateway
```

2. 运营打开 `https://<域名>/admin/`，用 `admin` + 初始密码登录；确认**绑定域名**（及证书）。
3. **新建租户** → 复制**注册链接** `https://<域名>/register/#<token>` 发给客户。
4. 客户打开注册链接：设置自己的后台用户名/密码与联系人信息。
5. 客户打开 `https://<域名>/console/` 登录租户后台，可随时：
   - 上传 / 更新 `pk_internal.pem`（内网重装后可再传）
   - 绑定 / 更新飞书凭据（或 mock）
   - 下载 `pk_gateway.pem` 给 ATM；必要时重新生成网关密钥对
6. 客户内网：`sudo ./fdt install intranet --tenant <id>`（与租户 id 一致）。
7. 飞书回调：`https://<域名>/callback/<tenantId>`；网页应用主页仍为 `/app/`。

网关侧为每个租户**自动生成并托管 `SK_网关`**；客户不上传网关私钥。配置变更热加载进 `gateway.Service`。

#### 也可用 tenants.json 批量预置

```bash
sudo ./fdt install gateway --tenants ./tenants.json
# 见 config/tenants.example.json
```

或旧命令：`fdt-gateway -tenants /etc/fdt/tenants.json`。

#### 其它

- **路由与隔离**：按帧头 tenant 选密钥；ATM 只信任本租户 `pk_gateway.pem`。
- **自部署单租户**：`--bundle gateway.tgz`；仍可用 `/admin` 继续加租户。
- **安全**：共享网关可见清单元数据；改掉初始 `ADMIN_PASSWORD`；邀请链接 7 天过期可换发。详见技术方案 §13.4。

## 5. 部署飞书网页应用（用户扫码入口）

**为什么需要它**：飞书原生审批不能"扫外部离线签名二维码自动建实例"，且建实例必须在网关服务端（需飞书凭据+验签）。入口页只做三件事：`scanCode` 扫 QR#1 → POST 给网关 → 审批通过后展示 QR#2。**审批引擎仍是飞书原生**，入口只是"扫码发起 + 出码展示"的薄壳。

> **2025 年起飞书对新租户关闭小程序新建入口**，本项目改用官方推荐的**网页应用（H5）**。仓库 `miniapp/` 仅作历史参考；运行时代码在 `webapp/`，由网关二进制内嵌并托管在 `/app/`。

### 5.1 前置

- 飞书开放平台创建/使用**企业自建应用**（可与审批用同一应用）。
- 应用能力 → **添加「网页应用」**（不要找「小程序」——新租户没有该项）。
- 网关已按 §4 部署完毕，具备公网 HTTPS 域名。

### 5.2 入口地址（无需单独打包上传）

H5 已随 `fdt` 网关发布，打开：

```
https://fdt-gw.corp.example.com/app/
```

飞书后台「网页应用」→ **桌面端/移动端主页** 均填上述地址（或你的实际网关域名）。

源码在仓库：

```
webapp/
  index.html   # 页面
  app.js       # scanCode → /submit → 轮询 /qr2 → 显示 /qr2/png
  app.css
  embed.go     # go:embed，随网关二进制分发
```

联调（`MOCK_FEISHU=1`）时扫码不可用，页面提供**手动粘贴令牌**；生产接真飞书后点「扫码发起审批」。

### 5.3 域名与 JSAPI

在飞书后台同一应用中配置：

| 项 | 填什么 |
|---|---|
| 网页应用主页 | `https://<网关域名>/app/` |
| **H5 可信域名** | `<网关域名>`（调用 `scanCode` 必需） |
| 安全设置里其它域名白名单 | 同域一般可不另加；若前后端拆域再分别加 |

网关提供鉴权接口：`GET /jsapi/config?url=<当前页完整 URL>`（不含 `#`），前端用返回的 `appId/timestamp/nonceStr/signature` 调 `h5sdk.config` 后再 `tt.scanCode`。

证书须完整有效；自签需在企业设备预置信任。

### 5.4 端点对应关系

| 网页动作 | 调用方式 | 网关端点 |
|---|---|---|
| JSAPI 鉴权 | `GET` | `/jsapi/config?url=` |
| 扫码后提交令牌 | `fetch POST` | `/submit` body `{frame}` |
| 轮询审批状态/取码 | `fetch GET` | `/qr2?reqId=` |
| 展示放行二维码 | `<img src>` | `/qr2/png?reqId=` |
| H5 静态页 | 浏览器 | `/app/` |

### 5.5 真机调试

1. 网关生产模式（填好 `FEISHU_*`，`MOCK_FEISHU=0`）+ HTTPS。
2. 飞书工作台打开网页应用 → 点「扫码发起审批」→ 扫 Portal 上的 QR#1。
3. 审批人在飞书批 → 页面轮询到 `APPROVED` → 显示 QR#2。
4. 用户持码到 ATM：**先插 U 盘再扫码**取数。

### 5.6 发布

1. 后台改主页/可信域名/权限后，走「版本管理与发布」→ 创建版本 → 管理员审核。
2. 设置**可用范围**（限申请人所在部门/成员）。
3. 改 H5 逻辑只需重新 `make release` 并更新网关二进制（或替换静态资源），一般不必改飞书后台（主页 URL 不变）。

### 5.7 注意

- `scanCode` 是**单码识别**——QR#1/QR#2 设计为单帧；超大清单走摘要降级而非多帧动画。
- QR#2 由网关用 `SK_网关` 签、`/qr2/png` 渲染；H5 只展示，不接触文件。
- **多客户 SaaS**：一个共享网页应用即可——帧头带 tenant，网关路由；跨公司时用商店应用（ISV），主页仍指向共享网关 `/app/`。

## 6. 部署 ATM 摆渡终端

### 6.1 硬件与系统

- 一体机 + 扫码枪（或摄像头）+ 指定 USB 数据口 + 触摸屏。
- **扫码枪务必设为 USB CDC/虚拟串口模式**，不要用 HID 键盘模式。**为什么**：HID 模式下二维码内容会被当键盘输入注入，构造恶意码可注入命令（风险 H1）。串口模式下应用把扫码内容当**纯数据**读取。
- **摄像头扫码**：`-camera /dev/video0`（需本机 `ffmpeg`；V4L2 抓帧后 gozxing 解码）。只接受 `FDT1.` 前缀帧，与扫码枪同一套 `SanitizeScan`。可在 `fdt.env` 设 `CAMERA=/dev/video0`。
- 若只能用 HID：应用需独占抓取输入、内容必须匹配 `FDT1.` 前缀并验签后才处理，绝不进 shell（`internal/atm/scanner.go` 的 `IsFDTPayload` 是第一道过滤）。

### 6.2 注册设备（防假 ATM，风险 M1）

在**内网** Portal 主机上，用一次性参数把这台 ATM 登记进库（`-register-device` 会写入 `devices` 表）：

```bash
# 生成一个随机设备凭据（生产用设备证书指纹）
SECRET=$(openssl rand -hex 32)
./bin/fdt-portal -db /var/lib/fdt/fdt.db -internal-key /etc/fdt/keys/sk_internal.pem \
  -staging /var/lib/fdt/staging -register-device atm-01 -device-secret "$SECRET"
# 记录 $SECRET，配置到该 ATM；启动后 Ctrl-C 退出（仅为注册）
```

datasvc 会校验请求头 `X-Device-ID` + `Authorization: Bearer <secret>` 与库中 `devices.cert_fingerprint` 一致且 `status=active`，否则 401。**生产用 mTLS 客户端证书**替代共享 secret。

### 6.3 放置公钥

把 `pk_gateway.pem` 拷到 ATM 的 `/etc/fdt/pk_gateway.pem`（只读）。ATM **只存公钥**，离线即可验 QR#2。

### 6.4 启动 ATM 程序

#### ATM 触屏 UI 端口与 HTTPS

ATM **网页/触屏 UI** 与 Portal 数据口分离：

| 配置 | 含义 | 默认 |
|---|---|---|
| `ATM_UI_LISTEN` | UI 监听，可改 `0.0.0.0:80` / `0.0.0.0:443` | `0.0.0.0:9080` |
| `ATM_UI_TLS=1` | UI 启用 HTTPS | 关 |
| `ATM_UI_TLS_CERT` / `ATM_UI_TLS_KEY` | UI 证书与私钥 PEM | `KEYS_DIR/server.pem` · `server.key` |
| `ATM_UI_URL` | 浏览器/Kiosk 打开的 origin（如 `https://127.0.0.1`） | 按 listen+TLS 推导 |
| `DATA_URL` / `IMPORT_URL` | 连 Portal **固定数据口** | `http://<portal>:8081/data` · `…/import` |

`fdt.env` 内已含注释示例。要点：

| 场景 | `ATM_UI_LISTEN` | `ATM_UI_TLS` | `ATM_UI_TLS_CERT` / `KEY` | `ATM_UI_URL` |
|---|---|---|---|---|
| 默认 HTTP 9080 | `0.0.0.0:9080` | `0` | **留空即可**（不读证书） | `http://127.0.0.1:9080` |
| HTTP 80 | `0.0.0.0:80` | `0` | **留空** | `http://127.0.0.1` |
| HTTPS 443 | `0.0.0.0:443` | `1` | 必填 PEM 路径 | `https://127.0.0.1` |

```bash
# 无证书（HTTP 80）
ATM_UI_LISTEN=0.0.0.0:80
ATM_UI_TLS=0
ATM_UI_TLS_CERT=
ATM_UI_TLS_KEY=
ATM_UI_URL=http://127.0.0.1

# 有证书（HTTPS 443）
ATM_UI_LISTEN=0.0.0.0:443
ATM_UI_TLS=1
ATM_UI_TLS_CERT=/opt/fdt-atm/etc/keys/server.pem
ATM_UI_TLS_KEY=/opt/fdt-atm/etc/keys/server.key
ATM_UI_URL=https://127.0.0.1

# 拉数仍走 Portal :8081（与 UI 无关）
DATA_URL=http://10.0.0.5:8081/data
IMPORT_URL=http://10.0.0.5:8081/import
```

> `ATM_UI_TLS=0` 时证书两项可空、可注释、可删除。绑定 80/443 通常需 root 或 `setcap`；自签证书需信任或仅本机 kiosk。

当前 `fdt-atm` 也支持**开发 CLI**（模拟 USB + 从参数/stdin 读 QR#2），`-mode export|import`。

**导出（默认）**：无盘扫码→拒绝；有盘→验签 QR#2→拉数据→写盘→回读校验 Merkle→CAS 核销。

```bash
./bin/fdt-atm -mode export \
  -db /var/lib/fdt/fdt.db -gateway-pub /etc/fdt/pk_gateway.pem \
  -datasvc-url http://10.0.10.5:8081 \
  -device-id atm-01 -device-secret "$SECRET" \
  -usb-dir /mnt/usb -usb-serial "$(lsblk -ndo SERIAL /dev/sdb)" \
  -qr2 "FDT1....."
```

**导入**分两阶段（中间隔一次飞书审批）：

```bash
# 阶段1：插源U盘 → 索引 → 建单 → 出 QR#1（同时写 PNG 供网页应用扫）
./bin/fdt-atm -mode import -import-phase start \
  -db /var/lib/fdt/fdt.db -gateway-pub /etc/fdt/pk_gateway.pem \
  -importer-url http://10.0.10.5:8082 \
  -device-id atm-01 -device-secret "$SECRET" \
  -usb-dir /mnt/usb -usb-serial USB-SER-1 -qr-out /tmp/qr1.png \
  -applicant-id e1234 -applicant-name 张三 -reason "导入客户资料" -cls confidential
# → 打印 申请单ID 与 QR#1 令牌；用飞书网页应用扫 /tmp/qr1.png 走审批，得到 QR#2

# 阶段2：扫 QR#2 → 流式上传U盘 → 隔离区 → 防换盘校验 → 扫描 → 释放/拦截
./bin/fdt-atm -mode import -import-phase complete \
  -db /var/lib/fdt/fdt.db -gateway-pub /etc/fdt/pk_gateway.pem \
  -importer-url http://10.0.10.5:8082 \
  -device-id atm-01 -device-secret "$SECRET" \
  -usb-dir /mnt/usb -usb-serial USB-SER-1 \
  -req-id <上一步的申请单ID> -qr2 "FDT1....."
```

> 生产 Kiosk 会把这两阶段合到触屏界面里（插盘→显示 QR#1→等待扫码→自动完成），CLI 仅为开发/联调。QR#1 PNG 由 `-qr-out` 落地，真机上是屏幕直接显示。

### 6.5 生产化 ATM（上生产前必做）

- **真实 USB 检测**：用 udev 监听热插拔替换 `MockManager`；插入后先只读挂载探测容量/写保护/文件系统；**USB 设备类白名单**（仅 Mass-Storage，拒绝 HID/复合设备，防 BadUSB）；关闭自动运行。
- **写盘安全**：数据经 tmpfs 内存盘直写、用后安全擦除（`streamAndWrite` 已流式哈希，落盘残留清理需补）。
- **Kiosk 锁定**：全屏单应用自启+看门狗；禁 shell/tty/快捷键；`authorized_default=0` 只授权指定 USB 口；网络白名单只通 datasvc/审计服务。
- **时间同步**：接内网 NTP。**为什么**：QR#2 有效期依赖时钟；时钟漂移/被改可绕过有效期（风险 H5）。核销的一次性已由 nonce+CAS 保证，不完全依赖时间。
- **UI**：把 CLI 换成触屏 Kiosk 界面（状态机在 `internal/atm/kiosk.go` 已就绪，UI 只是它的壳）。

### 6.6 修改 Portal / ATM 表单字段，以及飞书如何匹配

| 端 | 配置 | 作用 |
|---|---|---|
| Portal | `/etc/fdt/form-fields.json` 或管理后台「提交表单字段」 | 导出申请用户表单；可「导出飞书表单 JSON」 |
| ATM | `/etc/fdt/import-fields.json`（`ATM_IMPORT_FIELDS`） | 导入申请用户表单；自定义 `key` 原样进 `extras` |
| 网关 | `feishu-form.json`（`formFile` / `-feishu-form`） | `field` → 飞书控件真实 `id` |
| 飞书 | 审批定义表单 | 控件 id 与网关 JSON 一致；密级逻辑名为 **`class`**（来自 `cls`） |

改字段后必须同步飞书模板 + 网关映射，否则审批页空白或建实例失败。步骤与示例见 [一键部署.md](一键部署.md)「改字段后，飞书审批如何匹配」与 [飞书接入指南.md §8](飞书接入指南.md#8-创建审批定义表单字段对齐)。Windows ATM 见 [Windows-ATM.md](Windows-ATM.md)。

### 6.7 导入操作（U盘 → 内网）

导入服务随 `fdt-portal` 启动（`-importer-addr`，默认 `127.0.0.1:8082`；需 `-gateway-pub` 提供 PK_网关 才启用），隔离区/目标目录由 `-quarantine`/`-target` 指定。

流程（`atm.Kiosk`）：
1. **插源U盘 → `StartImport`**：索引U盘、算 Merkle、调内网 importer 建单并签 QR#1（`dir=import`）；无盘同样拒绝。
2. 手机网页应用扫 QR#1 → 飞书审批（与导出同一套网关/网页应用）。
3. **扫 QR#2 → `CompleteImport`**：ATM 先本地验 QR#2（有效期/方向/reqId），再把U盘内容**流式上传**到 importer。
4. importer 服务端：**再次验 QR#2（PK_网关）→ 写入隔离区 → 重算 Merkle 必须等于已批准指纹（防审批后换盘）→ AV/DLP 扫描**：
   - 通过 → 释放到目标目录、状态 `RELEASED`、CAS 核销、审计；
   - 命中 → 状态 `BLOCKED`、保留隔离区取证、**不释放不核销**、审计告警。

**注意**：`RuleBasedScanner` 是开发用（标记 EICAR 与可执行扩展名），生产必须换真实 AV/DLP 引擎；释放目标目录应受访问控制，导入数据默认落地即视为已入内网。

## 7. 首次端到端联调

**离线冒烟（不依赖飞书/硬件，验证内网逻辑）**：

```bash
./bin/fdt-demo
```

看到 12 个 ✓（建单→签QR#1→建审批→双控签QR#2→无盘拒扫→插盘兑付→REDEEMED→审计链OK→重放被拒）即内网核心链路正常。

**真实联调（分三段验证）**：

1. **内网段**：浏览器访问 `http://<portal>:8080/`（Portal 自带前端，同源无跨域），填数据目录建单，确认显示出 QR#1 图片、清单模式与 Merkle 根。
2. **DMZ+飞书段**：手机打开网页应用扫 QR#1 → 网关日志应显示验签通过、建实例成功 → 飞书里审批通过 → 页面显示 QR#2 图片。（先用 `-mock=true` / 粘贴令牌打通链路，再切 `-mock=false` 接真飞书。）
3. **ATM 段**：插 U 盘 → 扫 QR#2 → 观察写盘进度 → 完成后 U 盘里应有数据、申请单变 REDEEMED、审计新增 redeemed 事件。
4. **负向验证**：不插盘扫码应被拒；同一 QR#2 再扫应提示已核销；篡改数据应因 Merkle 根不符被拒并回滚。

**为什么分段**：三区分属不同网络，一次性联调难定位。按"内网→DMZ/飞书→ATM"逐段确认，问题好隔离。

## 8. 运维

### 8.1 备份

- 内网库 `/var/lib/fdt/fdt.db*`（含 WAL）定期冷备到内网备份系统。
- 私钥离线备份（保险柜）。
- **为什么**：库丢了＝申请单/审计/核销状态全丢；私钥丢了＝无法签发验证。

### 8.2 密钥轮换

令牌带 `kid`。轮换时：生成新密钥对→网关/ATM 同时信任新旧 `PK`（按 `kid` 选择）→切换签发用新 `SK`→旧令牌过期后下线旧 `PK`。ATM 需重新分发新 `pk_gateway.pem`。

### 8.3 审计与合规

- `store.RecentAudit` 读最近事件；`store.VerifyAuditChain` 校验哈希链完整性（定期跑，检出篡改）。
- 导出审计到 WORM 存储长期留存。审计字段覆盖：谁申请→谁审批(飞书审批ID)→哪台ATM→几点→写到哪个U盘序列号→数据Merkle根。

### 8.4 监控

- 健康检查：各服务 `GET /healthz`。
- 关键告警：重复导出事件（`usb_ops.result=duplicate`）、Merkle 校验失败回滚、审计链校验失败、datasvc 401（疑似假 ATM）。

### 8.5 过期清理

`store.ExpireStale` 把过期仍 PENDING 的申请单置 EXPIRED，可用定时任务调用。staging 里对应快照按保留策略清理。

## 10. 安全验收清单（上线前逐条勾）

- [ ] 内网主机 `iptables`/路由确认**无任何**到互联网/DMZ 的出站。
- [ ] DMZ 网关**不能**路由到内网区（双向隔离，仅手机/飞书可达）。
- [ ] `sk_*.pem` 权限 0600、属主正确；私钥未出现在日志/备份明文/镜像里。
- [ ] 网关 `-mock=false`，飞书回调 Encrypt Key/Verification Token 已配且回调限源。
- [ ] 网关启动**未加** `-mock`（日志无自动审批告警）；Portal `-identity` 非 mock（无 pass123 弱口令样例账号）。
- [ ] Portal 设置了 `-source-root`（或已改 multipart 上传），越界 `sourceDir` 被拒。
- [ ] 飞书审批控件 id / field 与网关 `feishu-form.json`、Portal/ATM 自定义字段一致；`approval_code` 正确。
- [ ] 飞书网页应用主页为 `https://<网关>/app/`；H5 可信域名已加网关域名。
- [ ] Portal Basic 认证与 LDAP 均走 TLS（LDAPS/StartTLS）；服务账号只读；用户名过滤器已 `EscapeFilter` 转义。
- [ ] `SK_网关` 在 HSM 内、启用双控；软件私钥文件已删除。
- [ ] 每台 ATM 只存 `pk_gateway.pem`，无私钥；设备已在 `devices` 表注册。
- [ ] 扫码枪为串口模式；非 `FDT1.` 前缀内容被拒。
- [ ] USB 仅授权指定口、设备类白名单、禁自动运行。
- [ ] 负向测试全过：无盘拒扫 / 重放拒 / 篡改数据 Merkle 拒并回滚 / 假 ATM 401。
- [ ] `VerifyAuditChain` 通过；审计已镜像到 WORM。
- [ ] 内网 NTP 正常，各机时间同步。
