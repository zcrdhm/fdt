# FDT 一键部署（少文件版）

设计上仍是三个信任域，但**交付物只有一个二进制**。每台机器一条命令装完。

## 你手里最终只有这些

| 机器 | 需要的文件 |
|---|---|
| 构建机 | 源码 → `make release` 得到 **`fdt` 一个文件** |
| 内网服务器 | `fdt` |
| DMZ 网关 | `fdt` + U 盘上的 **`gateway.tgz`（内网安装时自动生成）** |
| ATM | `fdt` + U 盘上的 **`atm-01.tgz`** |
| 手机 | 飞书**网页应用**（主页指到网关 `/app/`，见部署说明 §5） |
| 共享多租户网关 | `fdt` + `tenants.json`（每客户密钥，见下） |

密钥、systemd、目录、数据库都由 `install` 自动生成，**不必手拷一堆 pem**。

## 三步

```bash
# 0) 构建机（有 Go）
make release
# 得到 dist/fdt  —— 拷到三台机器即可

# 1) 内网服务器（多租户客户把 --tenant 改成自己的 id，如 acme）
sudo ./fdt install intranet --tenant default
# 浏览器打开 http://<内网IP>:8080/
# U 盘拿走:
#   /var/lib/fdt/outbox/gateway.tgz
#   /var/lib/fdt/outbox/atm-01.tgz

# 2a) DMZ 单租户网关
sudo ./fdt install gateway --bundle ./gateway.tgz --mock   # 联调：HTTP :8090
# 生产（推荐 Let's Encrypt 自助证书，无需 nginx / 手拷 pem）：
#   sudo ./fdt install gateway --bundle ./gateway.tgz \
#     --domain fdt-gw.example.com --email ops@example.com
#   # 或装好后在 /admin：「绑定域名」→ 检测 DNS →「申请证书」
#   # 需 DNS 指向本机，放行 80/443

# 2b) DMZ 多租户共享网关（一套网关服务多客户）
# 准备 tenants.json（见 config/tenants.example.json），相对路径相对该文件：
#   ./acme/pk_internal.pem  ./acme/sk_gateway.pem  …
sudo ./fdt install gateway --tenants ./tenants.json
# 密钥会落到 /etc/fdt/tenants/<id>/，配置为 /etc/fdt/tenants.json
# fdt.env 里 TENANTS_FILE 已写好；证书仍放 /etc/fdt/tls/

# 安装结束会打印运营后台初始密码（ADMIN_PASSWORD）
# 运营: https://域名/admin/  → 新建租户 → 复制「注册链接」给客户
# 客户: 打开注册链接设账号 → https://域名/console/ 登录
#       在后台上传 pk_internal.pem、绑定飞书、下载 pk_gateway.pem（可反复更新）
# 飞书网页应用主页 = https://域名/app/ ；回调 = https://域名/callback/<tenantId>

# 3) ATM（Linux）
sudo ./fdt install atm --bundle ./atm-01.tgz --server http://<内网IP>:8081
fdt-atm-ui                                          # 网页/触屏界面 → http://127.0.0.1:9080/
# USB 默认 sysfs 真机：插入 U 盘后自动挂到 /mnt/fdt-usb（或桌面已挂载路径）
fdt atm -qr2 'FDT1....'                             # 导出兑付（粘贴令牌）
fdt atm -camera /dev/video0                         # 摄像头扫 QR#2（需 ffmpeg）
fdt atm -scanner /dev/ttyACM0                       # 串口扫码枪
# 联调假盘才用: USB=mock + USB_DIR=…；真机: USB=sysfs USB_MOUNT=/mnt/fdt-usb

# Windows ATM：交叉编译 fdt.exe + 手工目录，见 docs/Windows-ATM.md
```

网关装好后可用浏览器打开 `https://域名/app/`（mock 下用「手动粘贴令牌」）。

## 装完目录长什么样

```
/opt/fdt/bin/fdt          # 唯一程序
/etc/fdt/fdt.env          # 唯一配置文件
/etc/fdt/keys/            # 本角色需要的密钥（install 自动放好）
/var/lib/fdt/             # 数据库、暂存、会话
/etc/systemd/system/fdt.service
```

## 内网端口（Portal UI vs ATM 传数）

内网**两个端口**，职责分开、不做同端口兼容：

| 端口 | 用途 | 可改？ |
|---|---|---|
| `LISTEN`（默认 `0.0.0.0:8080`） | 只跑 Portal / 管理页 | **可改**（见下） |
| **固定 `0.0.0.0:8081`** | 只跑 `/data` `/import`（ATM 传数） | **不可改**；访问 `/` 会 404，无 Portal 页面 |

防火墙对 ATM 网段**只放行 8081**；不要把 `LISTEN` 端口开给 ATM 网段。

### Portal 如何改网页端口

改内网机上的 `/etc/fdt/fdt.env`：

```bash
sudo sed -i 's/^LISTEN=.*/LISTEN=0.0.0.0:9088/' /etc/fdt/fdt.env   # 例：改成 9088
# 或手工编辑：
#   LISTEN=0.0.0.0:9088
sudo systemctl restart fdt
```

- 浏览器改访问 `http://<内网IP>:9088/`（以你设的端口为准）。
- **不要**把 `LISTEN` 设成 `…:8081`（启动会直接报错：8081 已固定给 ATM 数据口）。
- 改完后若有反向代理 / 防火墙，同步放行新端口；**ATM 的 `DATA_URL`/`IMPORT_URL` 仍指向 `:8081`，与 Portal 网页端口无关**。

### Portal 如何改导出表单字段

Portal 用户可见字段在内网 **`/etc/fdt/form-fields.json`**（`FORM_FIELDS_FILE`），也可用管理后台改：

1. 浏览器打开 Portal → 管理员登录 → **管理** →「提交表单字段」
2. 增删用户字段（`source=user`），保存后 **Portal 立刻生效**
3. 点「**导出飞书表单 JSON**」，得到网关要用的控件映射模板

内置字段 `reason`、`cls` 必须保留。自定义字段通过 `feishuField`（默认同 `key`；`cls` 固定映射为飞书逻辑名 **`class`**）进入 QR#1 的 `extras`，再由网关填进审批表单。

### ATM 如何改「导入申请」表单字段

字段由 **ATM 本机 JSON** 决定，**不读** Portal 的 `form-fields.json`。安装后默认文件：

- Linux：`/etc/fdt/import-fields.json`（`fdt.env` 里 `ATM_IMPORT_FIELDS=` 指向它）
- Windows：与 `fdt.env` 同目录的 `import-fields.json`（或设 `ATM_IMPORT_FIELDS=`）
- 仓库示例：`config/atm-import-fields.example.json`

编辑示例（加一个「接收方」）：

```json
{
  "version": 1,
  "fields": [
    {
      "key": "reason",
      "label": "事由",
      "type": "text",
      "required": true,
      "default": "导入资料",
      "order": 10,
      "enabled": true,
      "builtin": true
    },
    {
      "key": "cls",
      "label": "密级",
      "type": "select",
      "required": true,
      "options": ["internal", "confidential", "secret"],
      "default": "confidential",
      "order": 20,
      "enabled": true,
      "builtin": true
    },
    {
      "key": "receiver",
      "label": "接收方",
      "type": "text",
      "required": false,
      "order": 30,
      "enabled": true
    }
  ]
}
```

规则摘要：

- 类型：`text` / `textarea` / `select` / `number`；`select` 必须有 `options`（可用 `值|显示名`）。
- `key`：小写字母开头，`[a-z0-9_]`，最长 32；**启用中的字段必须包含 `reason`、`cls`**（内置，进 QR#1 核心字段）。
- 其它 `key` 原样写入 `extras`（ATM **没有** `feishuField` 改名，飞书侧逻辑名 = 这个 `key`）。
- 勿占用系统逻辑名：`req_id` / `applicant` / `dept` / `reason` / `class` / `merkle_root` / `file_count` / `total_size` / `manifest` / `direction`（`dept` 是登录人部门，不是自定义字段）。
- `enabled: false` 可隐藏字段；U 盘路径选择器是 UI 固定项，不在此 JSON 里。

改完后**重启 ATM UI** 生效：

```bash
# Linux（若用 fdt-atm-ui / 前台进程，停掉再开）
fdt-atm-ui
# 或
fdt atm -env /etc/fdt/fdt.env -ui
```

Windows：停掉 `fdt.exe atm … -ui` 后再启动；也可启动参数 `-import-fields C:\fdt-atm\etc\import-fields.json`。

### 改字段后，飞书审批如何匹配

两端改字段只影响本机表单；**审批里能否看见、能否建实例**，取决于网关 `feishu-form.json` 与飞书审批定义是否对齐。链路：

```
Portal form-fields / ATM import-fields
        ↓ 写入 QR#1（reason、cls + extras）
网关 BuildApprovalForm（field → 控件 id）
        ↓
飞书审批定义里的表单控件
```

| 来源 | 本机配置 | 进入飞书的逻辑 field | 飞书侧要做什么 |
|---|---|---|---|
| 系统 | （自动） | `req_id` `applicant` `dept` `merkle_root` `file_count` `total_size` `manifest` | 审批模板保留对应控件 |
| 事由 | Portal/ATM 的 `reason` | `reason` | 多行文本控件 |
| 密级 | Portal/ATM 的 `cls` | **`class`**（注意不是 `cls`） | 单行/单选控件 |
| Portal 自定义 | `key` + 可选 `feishuField` | `feishuField`（默认=`key`） | 增加同名逻辑控件，并把真实 **控件 id** 写进网关 JSON |
| ATM 自定义 | `key` | **就是 `key`** | 同上；导入审批模板也要有该控件 |

推荐操作顺序（以 Portal 加「接收方」`receiver` 为例；ATM 同理，把 key 配成一致）：

1. **Portal**：管理后台加字段 `receiver`，`feishuField` 填 `receiver`（可留空，默认等于 key）→ 保存 →「导出飞书表单 JSON」。
2. **ATM**（若导入也要填）：在 `import-fields.json` 增加相同 `key: "receiver"` → 重启 ATM UI。导入/导出若希望审批页字段一致，**两边 key 用同一字符串**。
3. **飞书**：在对应审批定义（导出用 `FEISHU_APPROVAL_CODE`；导入若单独一套则用 `FEISHU_APPROVAL_CODE_IMPORT`）表单里加控件，标题可中文；记下飞书分配的 **控件 id**（常见 `widget_…`）。
4. **网关**：把导出的 JSON 里该项的 `"id"` 改成飞书真实控件 id，`"field"` 保持 `receiver`，例如：

```json
{"id": "widget_receiver_abc", "type": "input", "field": "receiver"}
```

放入网关可读路径，并让网关加载该文件：

- 多租户：`tenants.json` 里该租户的 `formFile` 指向该 JSON；或  
- 单进程旧入口：`fdt-gateway -feishu-form /etc/fdt/feishu-form.json`  
- 仓库模板：[`config/feishu-form.example.json`](../config/feishu-form.example.json)

5. 改完后重启网关；用真实扫码建实例验证。审批页空白或 OpenAPI 报控件错误 → 多半是 **id 未换成飞书真实 id**，或 **field 与 extras key / `class` 不一致**。

要点：

- 飞书控件 **显示名**随便起；对齐的是网关 JSON 的 **`field`（逻辑名）** 与 **`id`（飞书控件 id）**。
- 只改 Portal/ATM、不同步飞书模板 + 网关 JSON → 自定义值进不了审批表（或建实例失败）。
- 只改飞书、不改网关 JSON → 网关仍按旧 widget 列表填表，新控件为空。
- 更细的飞书后台截图步骤见 [飞书接入指南.md §8](飞书接入指南.md#8-创建审批定义表单字段对齐)。

## 日常命令

```bash
systemctl status fdt
systemctl restart fdt
fdt run                 # 前台跑（读 /etc/fdt/fdt.env）
fdt demo                # 不装机也能看通链路
fdt atm …               # 摆渡终端操作
```

## 和旧方式的关系

旧的 `fdt-portal` / `fdt-gateway` / `fdt-atm` / `fdt-keygen` 仍可分别编译，适合深度定制。新交付默认只发 **`fdt`**。完整安全加固（HSM、clamd、LDAP、回调 CIDR）仍可通过改 `fdt.env` 或旧命令行旗标启用，见 README「生产化开关」。

内网 LDAP 配置页仅管理员可见：安装时写入 `PORTAL_ADMIN_PASSWORD`，登录后点「管理解锁」；或设 `PORTAL_ADMIN_USERS=账号1,账号2` 免解锁。普通用户看不到该入口，接口返回 403。
